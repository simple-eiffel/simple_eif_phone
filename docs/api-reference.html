SIMPLE_EIF_PHONE

The app's one handle on the phone. Eiffel owns the loop: `wait_for_event' / `poll_event' deliver `last_event', and before they return, `lifecycle' and `touches' have already applied it. There are no callbacks into Eiffel: the C glue queues, Eiffel pulls. One handle per process; when the app's root returns, the glue finishes the activity and ends the process (research D-012).

Constants

Back_system: INTEGER = 0

Android also handles Back (finishes the app); the key is still delivered.

Back_app: INTEGER = 1

Back is consumed; only the app reacts.

PHONE_SCREEN

The window's pixel buffer, one frame at a time. `present_argb' copies a cairo-format ARGB32 image (native-endian 0xAARRGGBB words) to the screen at (0,0), clipped. It is the one seam a GPU path would replace (research D-005). `has_window' is the live truth from Android; see SIMPLE_EIF_PHONE's invariant for why it matches the lifecycle model at every delivery.

Status

has_window: BOOLEAN

Does Android currently give us a window?

in_frame: BOOLEAN

Is the buffer locked for drawing?

width: INTEGER

Window width in pixels (0 without a window).

Ensures

non_negative: Result >= 0

height: INTEGER

Window height in pixels (0 without a window).

Ensures

non_negative: Result >= 0

Ensures

still_in_frame: in_frame

Requires

Ensures

Invariant

PHONE_METRICS

Window size, density and the content rectangle: the area not covered by the status and navigation bars (or the on-screen keyboard). Insets are derived from it. Values are read from Android at `refresh'; SIMPLE_EIF_PHONE refreshes on window, configuration and content-rect events. Font scale is not here: the NDK has no getter for it (spec 03 A-6).

Ensures

non_negative: Result >= 0

inset_right: INTEGER

Pixels covered on the right.

Ensures

Ensures

Re-read every value from Android. The content rectangle is clamped to the window; an empty one from Android (none reported yet) means the whole window (Phase 2 RB-4).

Status

Codes

Failure_language: INTEGER = 2

PHONE_EVENT

One thing that happened on the phone: a lifecycle change, a touch or a key. Immutable. Exactly one family per event (or none, for a timed poll that ran out). Touch coordinates are window pixels, rounded; they may lie outside the window while a finger drags off the edge.

Access

kind: INTEGER

Event code (see PHONE_EVENT_KIND).

time_ms: INTEGER

Android uptime in milliseconds, masked to 31 bits by the glue: never negative; wraps to 0 after 2^31 ms (~24.8 days). Compare two times by their difference, not by `<'.

pointer_id: INTEGER

Finger id for touch events; -1 otherwise.

x, y: INTEGER

Window pixel position for touch events; 0 otherwise.

key_code: INTEGER

Android key code for key events; 0 otherwise.

service_code: INTEGER

For service results, the reason or outcome code; 0 otherwise.

text: READABLE_STRING_32

For service results, the path or message; empty otherwise.

Status

is_none: BOOLEAN

Is this "no event"?

is_lifecycle: BOOLEAN

Is this a lifecycle event?

is_touch: BOOLEAN

Is this a touch event?

is_key: BOOLEAN

Is this a key event?

is_service: BOOLEAN

Is this a result from a Java service?

Output

out_line: STRING_8

One-line description, e.g. "touch_down id=0 x=12 y=40 t=1234".

Ensures

Invariant

valid_kind: is_valid_kind (kind) one_family: is_none.to_integer + is_lifecycle.to_integer + is_touch.to_integer + is_key.to_integer + is_service.to_integer = 1 touch_has_id: is_touch implies pointer_id >= 0 non_touch_no_id: not is_touch implies pointer_id = -1 key_has_code: is_key = (key_code > 0) non_touch_no_position: not is_touch implies (x = 0 and y = 0) time_non_negative: time_ms >= 0

PHONE_LIFECYCLE

Where the app is in Android's life, built from delivered events. Pure Eiffel: no platform calls, so it is tested on the PC. Lenient by design (Phase 2 RB-17): it accepts any order of events Android may send and only refuses use after `destroyed'. Each event changes exactly the state its kind names (per-kind frame clauses). `resumed' also sets `is_started' (Android always starts before it resumes), so the model stays consistent even if an event is lost.

Status

is_started: BOOLEAN

Between `started' and `stopped'?

is_resumed: BOOLEAN

Between `resumed' and `paused' (in the foreground)?

has_window: BOOLEAN

Between `window_ready' and `window_lost'?

has_focus: BOOLEAN

Between `focus_gained' and `focus_lost'?

is_destroyed: BOOLEAN

Has `destroyed' been applied? (final)

window_generation: INTEGER

Number of `window_ready' events so far; lets apps drop caches tied to an older window.

last_applied: detachable PHONE_EVENT

Most recent event passed to `apply' (any family).

affects_state (a_k: INTEGER): BOOLEAN

Does lifecycle code `a_k' change this model?

apply (a_e: PHONE_EVENT)

Update the model for `a_e'. Touch, key and the non-state lifecycle events (resized, redraw, configuration, low memory, content rect) change nothing but `last_applied'.

recorded: last_applied = a_e down: a_e.kind = Kind_touch_down implies (active_ids |=| (old active_ids & a_e.pointer_id) and x_of (a_e.pointer_id) = a_e.x and y_of (a_e.pointer_id) = a_e.y) down_positions: a_e.kind = Kind_touch_down implies (xs_model |=| (old xs_model).updated (a_e.pointer_id, a_e.x) and ys_model |=| (old ys_model).updated (a_e.pointer_id, a_e.y)) move: (a_e.kind = Kind_touch_move and old is_active (a_e.pointer_id)) implies (active_ids |=| old active_ids and x_of (a_e.pointer_id) = a_e.x and y_of (a_e.pointer_id) = a_e.y) move_positions: (a_e.kind = Kind_touch_move and old is_active (a_e.pointer_id)) implies (xs_model |=| (old xs_model).updated (a_e.pointer_id, a_e.x) and ys_model |=| (old ys_model).updated (a_e.pointer_id, a_e.y)) stray_move_ignored: (a_e.kind = Kind_touch_move and not old is_active (a_e.pointer_id)) implies (active_ids |=| old active_ids and xs_model |=| old xs_model and ys_model |=| old ys_model) up: a_e.kind = Kind_touch_up implies active_ids |=| (old active_ids / a_e.pointer_id) up_positions: a_e.kind = Kind_touch_up implies (xs_model |=| (old xs_model).removed (a_e.pointer_id) and ys_model |=| (old ys_model).removed (a_e.pointer_id)) cancel: a_e.kind = Kind_touch_cancel implies active_ids.is_empty cleared: (a_e.kind = Kind_window_lost or a_e.kind = Kind_focus_lost or a_e.kind = Kind_destroyed) implies active_ids.is_empty non_touch_unchanged: (not a_e.is_touch and not clears_touches (a_e.kind)) implies (active_ids |=| old active_ids and xs_model |=| old xs_model and ys_model |=| old ys_model)

clears_touches (a_k: INTEGER): BOOLEAN
